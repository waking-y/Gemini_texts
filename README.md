## 🎯 一、led_callback 模块

本项目展示了现代嵌入式开发中经典的**“三层架构 + 工程管理”**模式，旨在帮助初学者从“面向过程”平滑过渡到“面向对象”的架构思维。

### 📁 1. 代码分层架构

项目严格按照“洋葱模型”进行目录划分，实现了业务逻辑与底层硬件的彻底解耦：

```
📁 Project_Root/
│
├── 📁 app/                 # 🏢 业务应用层
│   ├── main.c              # 项目入口与总控中心。负责顶层逻辑组装，通过调用驱动层 API，绝不直接操作硬件引脚。
│   └── board.c/h           # 板级支持包（BSP）核心。充当硬件配置表，定义 LED、按键等外设的引脚连接，是驱动与物理硬件的对接层。
│
├── 📁 driver/              # ⚙️ 驱动中轴层
│   ├── 📁 led/ & botton/   # 通用外设驱动目录，与具体物理电路板完全无关。
│   ├── *_core.c/h          # 驱动核心实现。包含点灯、按键中断处理等逻辑。只要芯片平台不变，代码可 100% 直接复用。
│   └── *_desc.h            # 外设描述符文件。定义结构体（如 led_desc、button_desc），作为硬件参数与驱动逻辑之间的桥梁。
│
├── 📁 firmware/            # 🧱 固件库层
│   └── STM32_StdPeriph     # 存放 STM32 官方标准外设库，提供寄存器操作、GPIO/EXTI/NVIC 等最底层驱动接口。
│
└── 📁 mdk/                 # 🛠️ 工程管理层
    └── Keil_Project        # 存放 Keil uVision 工程文件（.uvprojx）及中间件，负责工程的构建与编译管理。
```

### ✨ 2. 核心架构特性

  本项目专为**小白进阶**设计，摒弃了传统单片机开发中意大利面条式的代码，引入了以下高级特性：

- 🛡️ **基于句柄的极致封装**：对外隐藏硬件寄存器细节，应用层只能通过不透明指针（Handle）操作硬件。
- 🔄 **面向对象的回调机制**：采用 `Callback` 函数指针处理中断，彻底解决了底层驱动与上层业务的强耦合痛点。
- 📦 **配置驱动分离**：换引脚只需修改 `board.c` 配置表，驱动核心代码终身免修改。
